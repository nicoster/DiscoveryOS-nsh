# Patched nsh crates

This directory holds a vendored copy of `nsh-platform-windows` 0.6.0 with a
single upstream fix backported. It is wired in via `[patch.crates-io]` in
`runner-windows/Cargo.toml` — the runner is the native exe shipped in release
packages, so this is what makes released builds carry the fix.

Note: `nsh run` builds a separate development host under `.nsh/rust/`, which
is generated by the nsh CLI and does not inherit this patch. The dev host is
not a release artifact; only the packaged runner matters for distribution.

## Why this exists

Windows inputs render typed text through a windowless RichEdit. Its drawing
was transformed by the surface's scale, but RichEdit actually draws client
pixels in **GDI's DPI** units. These agree only on a monitor at the system's
scale. When the window sits on (or is moved to) a monitor with a different
scale, the text was drawn scaled and out of the field — invisible or clipped.

The fix adds a transform factor `k = GDI_DPI / (96 * scale)` so the ink lands
in the client rectangle at any monitor scale.

## Provenance

This is upstream nsh PR #2338 ("windows: Draw input text in place on a monitor
of another scale than the system's", fixes #2298, merged 2026-11-18), applied
by hand to the 0.6.0 crate. Two files differ from the published 0.6.0 crate:

- `src/text_input.rs` — `record()` scales the recorded drawing by
  `richedit::target_scale(...)` (the `Matrix3x2 { M11: k, M22: k, ... }` block).
- `src/richedit.rs` — adds `pub(crate) fn target_scale(hwnd, scale)`.

No other files were changed. The original 0.6.0 crate is unchanged upstream.

## When to remove this patch

Delete this directory and the `[patch.crates-io]` entries once nsh publishes a
stable release that includes PR #2338. Check the release notes / the
`nsh-platform-windows` source for `target_scale` before removing. As of this
writing it is in `main` and `nightly` but not yet in any stable tag (0.6.0 and
0.6.1 do not have it).

Keep the version here (`0.6.0`) and the version in the manifests' patch
declaration aligned when bumping nsh.
